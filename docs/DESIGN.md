# 無垠鍊成（Endless Crucible）設計文件

> 本文件記錄經過設計訪談定案的所有決策，是實作與內容撰寫的依據。
> 修改設計時請同步更新本文件。

## 1. 定位

| 項目 | 決策 |
|---|---|
| 類型 | 探索配方型元素合成（發現新元素為核心樂趣） |
| 規模 | 個人興趣作品，做到可公開分享的完成度；不做帳號、不做營利 |
| 平台 | 桌機與手機（觸控）皆支援，可安裝為 PWA、離線遊玩 |
| 語言 | 繁體中文；所有文字抽離到資料檔，保留多語系擴充空間 |
| 主題 | 古典煉金術，以水、火、土、風四元素起手 |
| 美術 | 文字 + emoji 呈現元素；暗色煉金工房視覺（深底、金／琥珀點綴） |
| 名稱 | 主標「無垠鍊成」，副標 *Endless Crucible* |
| 部署 | GitHub Pages（GitHub Actions 自動建置部署） |

## 2. 核心玩法

### 2.1 鍊成台

- 畫面**沒有自由畫布**，只有「鍊成台」：**3 個元素框** + 「鍊成」按鈕。
- 放入 **2 或 3 個**元素即可按「鍊成」；少於 2 個時按鈕停用。
- 放入方式：點擊元素清單中的元素 → 放進第一個空框；桌機亦可拖曳到指定框。
- 點擊框內元素 → 取出。
- 元素**不消耗、無限取用**；同一元素可重複放入（水＋水）。

### 2.2 配方規則

- 每組配方由 2～3 個材料組成（上限為設定值，見 §8）。
- **不分順序**：配方以「排序後的材料 id」作為鍵。
- 允許同元素自合。
- 一組配方 → 恰好一個產物；同一產物可以有**多組配方**（多條路徑）。
- 比例目標：約 80% 兩材料、20% 三材料，三材料配方集中在高階元素。

### 2.3 鍊成結果

| 結果 | 表現 |
|---|---|
| 新發現（一般） | 元素從熔液浮上來，名稱、描述直接寫在坩堝下方，鍋面泛起漣漪；**不跳視窗**，可以直接放下一組；元素框清空 |
| 新發現（里程碑） | 同時達成成就（含關鍵元素、終局元素、分類全收集、發現數門檻）時，才彈出置中卡片 |
| 已知產物 | 鍊成台顯示產物，不跳卡片；元素框清空 |
| 無反應 | 熔液暗一下、鍋口冒一縷煙，文字「這幾樣之間沒有共鳴」；**元素框保留**，方便替換其中一個；記錄此組合 |

- 若框內組合先前已失敗過，「鍊成」旁顯示「已試過」。
- 鍊成過程約 1.1 秒：熔液慢慢升溫、符文亮起、元素沉入鍋中。
- 鍊成結果可以點開該元素的典籍頁。

### 2.5 低壓力原則

這款遊戲以「放鬆探索」為前提，回饋設計遵守以下規則：

- **失敗不是錯誤**：不搖晃、不用警告色、不用往下掉的「答錯」音效，文案不帶責備（不用「還是」）。
- **不打斷**：一般新發現不跳視窗；只有里程碑才有完整演出。
- **發光只給正在發生的事**：熔液、鍊成中的法陣可以發光；標題、數字、按鈕用不發光的霧金。器物維持舊、手工的質感。
- **節奏放慢**：火焰平常慢慢燒，鍊成時只稍微旺一點，不快速閃爍。
- **不強調還差多少**：標題列只顯示「典籍已錄 N 頁」，總數放在成就頁。
- **取出元素**：滑過已放入的元素時變暗並出現 ×，不用紅框。

### 2.6 典籍

- 觸控長按藥櫃裡的元素（放開時翻開）、桌機按右鍵、或點鍊成結果，可以翻開該元素的典籍頁。
- 內容：分類、頁數（發現順序）、描述、鍊成方式（只列材料都已擁有的配方）、還能參與幾種未發現的反應。
- 可從典籍頁直接「放進坩堝」。

### 2.4 元素清單

- 搜尋、分類分頁、排序（發現順序／名稱）。
- **已用盡**標示：凡是用到該元素的配方，其產物都已發現 → 變暗並打勾。
- 桌機為側欄；手機為鍊成台下方的清單區（佔下半部，自行捲動）。

## 3. 內容

- 第一版約 150 個元素。
- 每個元素：穩定英文 `id`、名稱、emoji、一句描述、分類。
- 分類：基礎、天象、地貌、礦物、植物、生物、器物、奧祕。
- 初稿由 Claude 撰寫，使用者審核。
- 格式：YAML（見 §7），並由驗證腳本把關。

## 4. 進度系統

### 4.1 發現數

標題列顯示「典籍已錄 N 頁」；「已發現 N / 總數」放在成就頁（滑過標題列數字也看得到）。

### 4.2 提示

- 初始 3 次；每發現 5 個新元素 +1 次；成就也可獎勵提示次數。
- 只會挑選「**材料全部已發現、產物尚未發現**」的配方，優先挑階層最低者。
- 使用 1 次提示會鎖定一個目標配方，並分三層逐步揭露（後兩層免費，由玩家決定是否翻開）：
  1. 「◯◯ 還藏著未知的反應」（揭露一個材料）
  2. 揭露第二個材料
  3. 揭露完整配方
- 目標產物被發現後，提示自動結束。

### 4.3 成就

約 15～20 個，條件以資料描述：
- `count`：發現數達到門檻（10／25／50／100）
- `complete`：全部發現
- `category`：某分類全部發現
- `element`：發現指定元素
- 可設定 `reward.hints` 獎勵。

## 5. 音效與設定

- 音效：成功、失敗、新發現三種，以 Web Audio 即時合成（不需音檔），走柔和路線（慢起音、低通、小音量）；失敗是悶悶的冒泡聲。不做背景音樂。
- 工房環境聲（可開關，預設關閉）：柴火低鳴、木柴爆裂、偶爾冒泡，同樣即時合成；頁面切到背景時暫停。開關存在本機，不進存檔碼。
- 設定選單：靜音、工房環境聲、匯出／匯入存檔碼、重置進度（二次確認）、統計（嘗試次數、遊玩時間）。

## 6. 存檔

- 存在 `localStorage`。
- 可匯出／匯入**存檔碼**（`EC` 前綴 + 版本 + base64 JSON）。
- 存檔帶 `version`，載入時依序跑 migration。
- 存檔只記錄元素 **id**，改中文名稱不影響存檔；存檔中出現內容裡已不存在的 id 時直接忽略。

## 7. 內容資料格式

```
content/
  game.yaml                 # 全域設定（框數、材料數、提示參數、啟用的內容包、語系）
  packs/
    core/
      pack.yaml             # 內容包資訊、起始元素、分類
      elements.yaml         # 元素
      recipes.yaml          # 配方
      achievements.yaml     # 成就
  locales/
    zh-TW.yaml              # 介面文字
```

配方寫法（一行一組，不分順序）：

```yaml
- water + fire = steam
- air + air + energy = tornado
```

多個內容包會依 `game.yaml` 的 `packs` 順序合併；後載入的內容包可以新增元素與配方。

## 8. 擴充性設計

| 未來擴充 | 預留方式 |
|---|---|
| 4 個以上材料、更多元素框 | `game.yaml` 的 `slots`、`minInputs`、`maxInputs`；引擎以 N 個材料處理，不寫死 3 |
| AI 生成配方（混合模式） | 配方查詢抽象為 `RecipeResolver`（非同步介面），第一版實作為 `StaticResolver`；未來可串接 `ChainResolver(static → ai)` |
| 擴充內容包 | 元素、配方、分類、成就全部來自資料；載入時合併多個內容包 |
| 改名、調整配方 | 元素以穩定 id 識別，顯示名稱僅為資料 |
| 存檔格式變更 | 版本號 + migration 清單 |
| 多語系 | 介面字串集中在 `content/locales/`；元素名稱／描述未來可由語系覆蓋檔提供 |
| 新成就或提示規則 | 成就條件為「型別 + 參數」的資料，新增型別只需加一個判斷函式 |
| 新驗證規則 | 驗證腳本為規則清單，可逐條新增 |

**分層原則**：`src/core/`（配方、狀態、存檔、提示、成就、驗證）完全不碰 DOM，可獨立測試；`src/ui/` 只負責呈現與輸入。

## 9. 工程

- Vite + TypeScript + 原生 DOM；拖曳使用 Pointer Events，對話框使用原生 `<dialog>`。
- PWA：`vite-plugin-pwa`（manifest + service worker 預快取）。
- 測試：Vitest（核心邏輯 + 內容驗證）。
- CI：GitHub Actions → 型別檢查、測試、內容驗證、建置、部署到 GitHub Pages；任何一步失敗都不會部署。
- commit 訊息使用繁體中文。
